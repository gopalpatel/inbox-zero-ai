# inbox-zero-o365 Implementation Plan

**Goal:** Build a standalone O365-native email pipeline that processes Office 365 mailboxes (starting with user@example.com) through the same inbox-zero workflow, scanning mail across Inbox plus all included user folders/subfolders, while producing output files identical to the Gmail app's contract.

**Architecture:** Sibling directory to `inbox-zero/`, zero shared runtime code. O365-native internals (Microsoft Graph API), Gmail-compatible exports. Contract-first: schemas copied unchanged, validated by contract tests before any feature work.

**External vocabulary stays the same as the Gmail app:** use the same human-facing taxonomy and step names, especially `keep` / `filter` / `unsubscribe` and `filterStatus`. Internally, O365 implements "filter" via inbox rules, but exported manifests/logs/state should stay understandable to any existing consumer.

**Post-index retrieval guarantee:** the exported `messageId` in `data/batch-*.json` must be sufficient to later retrieve that exact message in full, by ID alone, with no folder lookup step.

**Review surface:** Google Sheets only. Excel Web is explicitly out of scope.

**Tech Stack:** TypeScript strict, Zod schemas, Microsoft Graph SDK (`@azure/identity` + `@microsoft/microsoft-graph-client`), Google Sheets API (for audit reports), Anthropic SDK (for LLM enrichment), Commander CLI, Vitest, Biome.
